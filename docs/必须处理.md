# 需要你做一次操作：彻底删掉 GitHub 上的历史残留

## 发生了什么

部署时为了让 Docker 镜像能用上知识库，我把 32 MB 的知识库快照（`kb_snapshot/`，1795 个文件）提交进了 Git。当前 `main` 分支已经**完全清理干净**（182 个文件，0 个知识库文件），但这个提交存在于 Git 历史里，GitHub 会保留悬空对象。

也就是说，虽然仓库页面和 `main` 分支上什么都看不到，但知道旧 commit SHA 的人仍可能通过旧提交读到知识库原文。赛题要求知识库不得对外传播，所以这件事需要收尾。

## 我做不了的

删除仓库需要 `delete_repo` 权限，你现在给我的 token 没有（报 403 `Must have admin rights to Repository`）。联系 GitHub Support 让它回收悬空对象也不是我能自动完成的。

## 最省事的做法（约 2 分钟）

**方案 A：让仓库彻底消失，重新建一个（推荐）**

1. 打开 https://github.com/cyhkbl/hongjian-huawei-pc-agent/settings
2. 拉到最底部，「Danger Zone」→ 「Delete this repository」
3. 按提示输入仓库名确认删除
4. 然后跑我写好的脚本重建：

```powershell
& 'D:\DeepSeekWorkSpace\hackathlon\hongjian\scripts\recreate_github.ps1
```

脚本会用本地的干净孤儿提交重新建仓库、推代码、补上描述和 topic，内容与现在完全一致，只是历史只有一条。

**方案 B：联系 GitHub Support**

在 https://support.github.com/ 开一个 ticket，说明「误提交了敏感资料，需要清除仓库 `cyhkbl/hongjian-huawei-pc-agent` 中悬空提交的缓存对象」。响应通常要几天，赶不上评审期。

## 确认做对了以后

跑 `scripts\final_audit.ps1`，看到「kb_snapshot: 0」和几个旧 SHA 显示「已不可读」就对了。

## 顺便说清一件事

魔搭创空间那边**不受影响**。那边本来就需要知识库才能跑，是我有意放的，镜像里也是它；那是部署到主办方平台的正常做法，和「公开发布到 GitHub」是两件事。
