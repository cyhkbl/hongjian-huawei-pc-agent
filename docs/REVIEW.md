## 六、双远端维护方式

两个仓库需要的内容不同，用两条分支维护：

- **`gh-main` → GitHub `main`**：不含 `kb_snapshot/`（主办方禁止对外传播知识库），177 个文件。
- **`master` → 魔搭 `master`**：含 `kb_snapshot/`，Docker 构建需要它，1982 个文件。

推送时**不要**把 `master` 推到 GitHub，也不要把 `gh-main` 推到魔搭。改代码后先提交到 `master` 推魔搭，再把改动 cherry-pick 或 checkout 到 `gh-main` 推 GitHub。

## 七、历史遗留问题（不在当前分支，但读者可能通过旧 SHA 访问）

GitHub 当前 `main` 已完全干净（`kb_snapshot` 0 个，直接访问知识库路径返回 404），但更早的旧 commit SHA 仍可能被 GitHub 的悬空对象缓存提供访问。清理需要 `delete_repo` 权限或联系 GitHub Support，做法写在 `docs/必须处理.md`。**魔搭创空间不受影响**，那边放知识库是部署的正常做法。
